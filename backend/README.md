# Backend administration

## Create the first administrator

Run this command from the `backend` directory after configuring `MONGO_URI` in
`.env`. The command creates an administrator using the email and password
provided in the environment. It is safe to repeat: an existing administrator
is left unchanged, while an existing non-admin account with that email causes
the command to stop without changing the account.

PowerShell:

```powershell
$env:ADMIN_EMAIL = "admin@example.com"
$env:ADMIN_PASSWORD = "choose-a-strong-password"
npm run admin:create
```

`ADMIN_NAME` and `ADMIN_PHONE` are optional. The account can sign in at
`/admin/login`.

## Admin API

- `GET /api/admin/dashboard` returns dashboard statistics and requires an
  administrator session.
- `GET /api/settings` returns storefront settings publicly.
- `PUT /api/settings` updates storefront settings and requires an
  administrator session.

Delivery fees and the free-delivery threshold are stored with the settings and
used by the server when calculating new order totals.

## eSewa payments

Local development defaults to eSewa's sandbox. Configure `ESEWA_ENVIRONMENT`
as `sandbox` and use the UAT product code and secret key provided by eSewa.
Production deployments must set `ESEWA_ENVIRONMENT=production` and supply the
merchant's production product code and secret key. Payment signatures are
generated by the backend; the browser posts the signed fields directly to
eSewa's checkout endpoint.
